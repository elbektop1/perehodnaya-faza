## О разработчике

Первый коммерческий проект. Java и PostgreSQL знает хорошо, логику
понимает, синтаксис JS/React/вёрстки — плавает, учится по ходу.
Код генерируется через Claude; роль разработчика — интеграция и отладка.

Как писать код:
- Комментарии лаконичные, профессиональные (этап обучающих комментариев
  пройден — писать как для коллеги, объяснять только неочевидное)
- Синтаксис пояснять простыми словами при вопросе, не в комментариях
- Давать только нужное сейчас

Рабочий процесс:
- Крупные задачи — через Plan mode: сначала план, после согласования
  выполнение по частям в заданном порядке
- После каждой части — короткий отчёт о сделанном, прежде чем идти дальше

## О проекте

Внутренняя система управления заказами для типографии (флексопечать
этикеток). Только для сотрудников, внешние клиенты не заходят.

Стек:
- Фронтенд: сейчас ванильный HTML/CSS/JS → потом React (PWA)
- Бэкенд: Java + Spring Boot (планируется)
- БД: PostgreSQL (планируется)
- Хостинг: физический сервер заказчика (12 ГБ RAM), Docker Compose

Демо для заказчика: https://elbektop1.github.io/artline-os/
(GitHub Pages, публичный репо `elbektop1/artline-os`, обновляется
загрузкой файлов вручную)

## РОЛИ — их 8 (обновлено по ответам заказчика)

1. **director** — Директор. Видит всё, калькулятор себестоимости (за PIN),
   отчёты, сотрудники. Логины выдаёт сам.
2. **assistant** — Помощник директора (Богомолова). Как менеджер, но без
   доступа к финансам, калькулятору себестоимости и данным по оплатам —
   точный набор прав уточняется у заказчика.
3. **manager** — Менеджер. Заводит заказы, назначает исполнителей,
   согласовывает макеты, общается с заказчиком.
4. **designer** — Дизайнер. Делает макеты, отправляет на согласование.
5. **production_manager** — Менеджер производства. Готовит флекс-формы
   после согласования макета. Видит ПЛАН ЗАКАЗОВ и может менять
   порядок/приоритет заказов. В выходные его функции берут печатники.
   (У заказчика этого человека зовут Щербакова.)
6. **economist** — Экономист = ЗАКУПЩИК / контрактный управляющий (НЕ бухгалтер).
   Заказывает материалы, считает себестоимость заказов, следит за расходами,
   предлагает более выгодные закупки. Работает с калькулятором себестоимости.
7. **accountant** — Бухгалтер. Классический бухучёт: счета, акты, оплаты.
8. **worker** — Печатник (в коде ключ "worker", в интерфейсе «Печатник»).
   Печатает на станке, отмечает готовность к отгрузке.

## ЦЕПОЧКА ЗАКАЗА И СТАТУСЫ

Статусы: new → design → rework → approval → (подготовка форм) →
production → ready → done

- **new** — Менеджер завёл заказ
- **design** — У дизайнера (делает макет)
- **rework** — На доработке (вернули с замечаниями)
- **approval** — На согласовании (макет готов, ждёт менеджера)
- **production** — В производстве (печатник печатает)
- **ready** — Готов к отгрузке (печатник отметил, ждёт подтверждения менеджера)
- **done** — Завершён

После согласования (approval → production) заявка идёт менеджеру
производства (готовит флекс-формы), затем печатнику. В выходные —
сразу печатнику.

Повтор БЕЗ изменения макета (orderType "repeat") идёт сразу на approval —
минуя design, сразу доступен менеджеру производства («Передать в
производство»). Повтор С изменением (orderType "repeat_changed") и новый
заказ — по полной цепочке, через дизайнера, без изменений.

## НОЖИ И ЛАЗЕР (логика высечки — по ответам заказчика)

Два разных способа высечки этикетки:

**Нож (штамп)** — для ВСЕХ флексо-машин (WEIGANG, BENGRAPHIC, GALLUS).
Используется при автоматическом съёме этикеток (аппликатор), больших тиражах.

**Лазер** — ОТДЕЛЬНЫЙ станок. Высекает по метке. Используется когда:
ручной съём этикеток, небольшой тираж, белая плёнка/бумага.
Требует чтобы на печати была предусмотрена метка — иначе лазер не сработает.

Логика при создании заказа:
1. Менеджер выбирает нож из базы (архив ножей в calculator.html)
2. Размер этикетки подставляется автоматически из параметров ножа
   (допускается погрешность ±1мм — заказчик иногда использует близкий
   размер, напр. нож 59×99 для этикетки 59×100)
3. Если подходящего ножа НЕТ в базе — зависит от тиража:
   - Малый тираж → предложить ЛАЗЕР
   - Большой тираж → заказать НОВЫЙ НОЖ

Новый нож:
- Срок: ~3 дня (идёт параллельно с заказом материала). Если заказали
  до 16:00 в рабочий день — привезут на следующий рабочий день
- Цена: зависит от размера, формы и материала (не фиксированная)
- На заказе нужна пометка «ожидает нож» + влияние на срок/цену

## Архитектурные принципы — НЕ НАРУШАТЬ

1. **Данные управляют поведением.** Логика в таблицах-объектах:
   TRANSITIONS (переходы+права), MENU_BY_ROLE (меню по ролям),
   справочники (MATERIALS, LAMINATION, INKS, MACHINES, ORDER_TYPES,
   KNIVES когда добавим). Расширение = строка в таблицу, не условие в коде.
2. **Статус и исполнитель раздельны:** order.status и order.assignee.
3. **Файлы:** index.html (структура) / style.css (стиль) /
   app.js (логика) / reference_data.js (справочники) / calculator.html
   (калькулятор). Стили не в JS, логика не в HTML.
4. **Никаких prompt()/confirm()** — только модальные окна, одна механика.
5. **Дизайн пересматривается по референсу заказчика** — тёплый светлый
   фон, сайдбар остаётся тёмным, сверху добавлена CMYK-полоска (голубой →
   пурпурный → жёлтый → почти чёрный, отсылка к печати). Актуальная
   палитра в :root (style.css):
   --bg:#F4F1EA (тёплый кремовый); --surface:#fff; --text:#16181D;
   --text-soft:#71757E; --border:#E4DFD4; --sidebar:#1c1917 (без
   изменений — подтверждено референсом); --accent:#d0201b (кирпично-
   красный, временно — на референсе заказчика акцент голубой #008FBE,
   не подтверждено явно, сменить одной строкой в :root когда подтвердят).
   Добавлены --green:#1F8A5B, --yellow:#F2C200, --red:#C23B2E,
   --cyan:#008FBE — цвета полоски карточки заказа и части бейджей
   (этап 1, см. ниже). Шрифты Manrope (текст) + Unbounded (цифры/акценты)
   — без изменений.
6. **Никакого localStorage/sessionStorage.**

- Фаза 10 (уведомления): адресный центр событий — `Store.notifications`
